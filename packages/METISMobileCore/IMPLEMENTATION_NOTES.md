# METIS Mobile Core implementation boundary

This Foundation-only Swift 6 package adds reusable pure decision logic; it is not a new SUITE-specific OS and does not replace the audited METIS services. Its fail-closed evidence and expected-version approach follow the reuse audit. Native capability adapters and the existing backend gateway remain separate integration work.

- All 28 Mobile Override §4 capability contracts are inventoried as `notConnected` by default. An enum case is not a working camera, USB, accessibility or background adapter.
- `ExecutionPlanner.choose` requires caller-supplied provider availability, measured time/cost/quality, resource estimates and privacy intent. It considers file/batch transfer, GPU/NPU, memory, heat, battery, network and concurrency. An ineligible candidate defers; no provider calls run here. Weights require real-device/product tuning.
- `ProxyPolicy.select` uses caller configuration and device resource budgets; it does not generate images. Critical resources defer, and insufficient budget never silently selects Original/full resolution.
- `JobCheckpoint` serializes a frozen input/revision, stable idempotency key, progress and resumable state. A durable queue, checkpoint repository, automatic recovery runner and iOS background task adapter are not connected.
- `ReleaseGate` blocks missing/failed/unknown/expired/mismatched/duplicate evidence. Its minimum registry has the 21 Mobile Override gates plus `macBuildAndTests`, `realRAWLoad100`, `realRAWLoad500`, `realRAWLoad1000` and `fullLifecycleSyncRecovery`. All five added gates require measured evidence; missing or unknown results block Mobile release even if the earlier gates pass. Mac build/load evidence, RAW-count evidence and iPhone/iPad physical-device evidence have separate requirement IDs and cannot satisfy one another. The trusted QA service must attest the actual environment and measurement behind each artifact, not relabel reports. Web completion is excluded. Commercial V1, App Store, security and all inherited gates must be supplied additionally; a partial registry or a locally constructed proof is not release authorization.

Tests are authored for capability completeness, route eligibility and heat/memory/offline/privacy, configurable Proxy selection, checkpoint resume/invariants and fail-closed release evidence. The assigned Windows environment has no confirmed Swift toolchain; the main agent owns build/test execution. These tests are **not reported as passed** here. Run `swift test --package-path packages/METISMobileCore` from the SUITE root on a configured Swift 6 host. iPhone/iPad device performance and interruption tests remain separate release requirements.

Two further tests cover the mandatory measured Mac/100/500/1000 RAW/full-lifecycle gates and verify that passing Mac/RAW evidence cannot clear either physical-device gate. Neither these tests nor simulated pass fixtures count as those actual measurements.
