# Mobile Release First — 変更指示の正本
2026-10-03。基本設計書SUITE_SPEC.mdと併せて適用する。

## 最優先方針
**MOBILE RELEASE > WEB RELEASE**
**Web完成はMobile Release Gateに含めない**

最新のMOBILE_OVERRIDE.mdを併用し、実装の着手順は同書13節（MOBILE COREから）を優先する。下記12項目は元の指示として保持し、Core確立後の共通バックエンド・認証・保存の依存関係を省略しない。
Web版より先に、iPhone・iPad版を完成させてリリースする。
Web対応は、iPhone・iPad版の完成条件およびリリース条件に含めない。
以後の実装判断・設計・QA・リリース判定は、すべてモバイル版を最優先とする。

## 既存仕様の完全継承
これまでの打ち合わせ、実装指示、確定済み仕様、合意済み要件をすべて継承する。
変更はリリース順序と実装優先順位のみ。撤回・削除・簡略化ではない。
既存機能、合意済み要件、UI／UX、画面構成、操作導線、編集機能、データ設計、保存仕様、セキュリティ要件、安全設計、運用要件、QA要件、リリース要件、その他の確定内容を勝手に削除・変更・置換しない。
今回後ろに回すのはWeb版の完成・公開のみ。Web向けを含む共通仕様、データ構造、バックエンド仕様、将来拡張前提は保持する。

3. 写真データ・編集データの保存基盤
4. iPhone版UI
5. iPad版UI

7. 編集履歴・復元
8. 書き出し・保存
9. iPhone／iPad実機テスト
10. モバイル版リリース準備
11. App Store公開
12. Web版対応

## iPhone
片手操作・タッチ操作を前提としたモバイル専用UIとして設計する。
主要編集操作が画面下部または親指の届きやすい範囲で完結する構成を優先する。
PC／Web向けUIを縮小して流用しない。

## iPad
iPhone版の単純拡大は禁止。以下を前提としたiPad専用レイアウトを実装する。
- 大きな写真プレビュー
- 常時表示可能な編集パネル
- ツールと写真領域の同時表示
- 横向き／縦向き双方への最適化
- Apple Pencil等のポインティング操作を阻害しないレイアウト

## 共通処理
API、認証、データモデル、写真保存、編集履歴、プリセット、書き出し処理などの共通ロジックはUI層から分離する。Web UI完成をモバイル版リリースの前提にしない。

## 初回リリース判定
完成判定対象はiPhone・iPad版。以下を満たし、既存の商用V1・QA・安全・リリース要件を満たしていれば、Web版未完成でもリリース可能とする。一覧で基本設計書81節や79節などを置き換えない。
- [ ] 写真の読み込み
- [ ] 基本編集
- [ ] 編集内容の保持
- [ ] Undo／Redoまたは編集履歴
- [ ] 保存・書き出し
- [ ] 異常終了時のデータ保護
- [ ] iPhone実機確認
- [ ] iPad実機確認
- [ ] タッチ操作に重大な阻害がない
- [ ] 主要導線に操作不能箇所がない
- [ ] 本番用バックエンドとの正常接続

## 実装・並列作業・完了条件
難しい設計を最優先。欠落監査を並行し、独立した重い実装とバグ潰しを最大限並列化する。12工程の依存関係を守り、Web完成を前倒ししない。
1. 勝手な再設計や全面リファクタは禁止。再利用可能な既存資産を調査し、破棄せず必要範囲で利用する。
2. サイドエージェントごとの担当ファイルと責務を固定。同じファイルや責務は被せず、最終統合はメインだけ。
3. ビルド・テスト・主要導線の実行結果を必須とし、メインが統合後の結果を確認する。
4. 未完成のダミー実装、モックだけの成功、未実行の試験を完成・合格として扱わない。
5. 最後に既存仕様との突き合わせ監査を必ず行い、実装済み・未実装・壊れた箇所を洗い出す。根拠がない項目は未確認と区別し、欠落を解消してから実装完了とする。

Astra Ultra使用中も、ある担当が詰まっても全体を止めず、依存しない調整・実装・テスト修正を並列継続する。推測で依存を飛ばしたりダミーに置換しない。
Sol引継ぎでは「今の状態・やったこと・残タスク・変更禁止事項」をHANDOFF.mdに明記する。

## 新規プロジェクトとの整合
最新のユーザー確認により、SUITEは新規プロジェクトで専用リポジトリ未作成だった。新規SUITEリポジトリ・基本骨組みの作成は明示的に承認済み。「既存実装を起点」はMETIS/Picasso/da Vinciの資産調査・再利用と、今後できるSUITE実装の維持に適用する。既存SUITEがあるという前提の旧作業メモは採用しない。

**SUITEは Mobile First ではなく Mobile Release First。**
**最初に公開する完成品をiPhone・iPad版とし、Web版はその後に追加する。**
**これまでの打ち合わせで確定した仕様は一切落とさない。**
