# EV3-0873–0875 Desktop ↔ iPad compatibility audit — 2026-10-04

Status: **NOT_CONNECTED in the SUITE product**. The repository contains a strict, data-only cross-device JSON preflight and separate Web and Apple implementations, but not an authenticated Desktop/iPad preset exchange or end-to-end restore/export workflow. This audit changes no product source, Recipe, Original, database or deployment.

## Primary source and interpretation

[Evoto's iPad FAQ](https://support.evoto.ai/evoto-ipad-faq/) says **most** PC presets can be used on iPad and vice versa. It also warns that settings unavailable on one device may apply differently or incompletely. It does not promise all presets, pixel-identical rendering, automatic cloud transfer of Originals/Proxies/Finals, preset-version conflict resolution, or a particular warning UI. The local source matrix `docs/EVOTO_AUDIT/EVOTO_FEATURE_MASTER.md` maps this to EV3-0873 Desktop→iPad, EV3-0874 iPad→Desktop, EV3-0875 unsupported settings partial/variable. “Desktop” in this audit means a desktop-class product; SUITE currently has Web in a desktop browser, **not** a native Windows/macOS app. Evoto behavior is not inherited by SUITE.

## Dedicated audit tests

`apps/web/tests/desktop-ipad-compat-completion-audit.test.mjs` is **4/4 PASS** for source/contract boundaries only: official sub-operation IDs, neutral Recipe and versioned metadata roundtrip, fail-closed Web-only adjustment, and disconnected Apple host/Proxy path. The test does not run Swift, Xcode, actual Desktop native code, authenticated cross-device sessions, iPad hardware, Cloud storage, RAW, or image equivalence. A PASS is an evidence-backed **gap finding**, not an EV3-0873–0875 completion claim.

1. Provide a real authenticated host/session for iPad and desktop-class Web using one server authority, then verify membership, Workspace/Project/Asset scope, immutable Original SHA and preset version on both ends. Do not equate Trial cookies, Node Workspace bearer and Cloudflare bindings.
2. Define a versioned per-device capability manifest for each Recipe/Preset stage and extension. Before apply, show exact unsupported fields and outcome choice; preserve the complete source preset and target edits. If rendering cannot support a setting, fail closed rather than silently applying an incomplete result. Test both directions and conflict/role revocation.
3. Connect Original/Proxy transfer and verified Final using the existing priority/Cloud Safe contract. Test re-entry on the second device, saved Recipe CAS, generated Final provenance and offline/resume without Original mutation.
4. Run Swift package, simulator, real iPad, desktop-class browser/native target, RAW, accessibility, network-loss and Cloud permission tests separately. None can be inferred from this data-only audit; keep the independent-feature completion count unchanged.
